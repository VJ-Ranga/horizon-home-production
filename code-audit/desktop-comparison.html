01 · Read this first

The frame plan is shared. The clocks are not.

Both desktop builds use the same 1–1125 frame timeline and the same section definitions. The main behavioral difference is how scroll smoothing and frame sampling are scheduled. The current build has the single-clock correction; the old 3100 build still runs Lenis and the frame driver in separate animation loops.

05 · Cleanup decisions

What to clean up before making them match

Priority 1

Unify the animation clock

Move the old Lenis advancement into the frame-driver loop. The same loop must advance smooth scroll, read the resulting scroll position, map the frame, and notify subscribers.

Priority 1

Keep one timeline source

Remove operational references to 720/840-frame plans where the live code uses 1–1125. Components should read SECTIONS, not copy frame windows.

Priority 2

Correct the fallback

Use the last painted image when the exact target is not decoded. A nearest future frame can make the background appear to jump ahead of the scroll position.

Priority 2

Separate timing from file density

Keep logical frame numbers and section timing unchanged when switching between default, HQ, 2x, 4x, and mobile assets.

Keep

Virtual holds

They are the correct method for readable content, carousels, and shared-background sequences. They add time without duplicating video frames.

Keep

Shared frame subscribers

Canvas, section layers, HUD, and content interactions should continue consuming one emitted frame value.

06 · Recommended path

How to make the old desktop behave like current

1

Freeze the shared contract

Keep LAB_LAST_FRAME = 1125, HERO_SETTLED_FRAME = 50, the 19 section windows, and 14px/frame.

No timeline redesign

This prevents a clock fix from changing content timing.

2

Port the single-clock driver

Advance Lenis inside the frame driver before calculating frameForScrollPx().

Desktop behavior

This is the main change required for matching current desktop.

3

Make loading temporally safe

Keep decoded images outside React, but use last-painted fallback and report logical integer frames.

Visual stability

Prevents future-frame jumps while assets decode.

4

Run section checkpoints

At every settled frame, test entry, hold start, hold end, exit, carousel freeze, and loop boundary.

60 Hz + 120 Hz

Record actual frame, scrollY, and painted file at each checkpoint.

5

Update documentation

Mark 720/840 documents historical, link this report, and keep timeline.ts as the source of truth.

Release hygiene

Prevents the two desktop builds from drifting again.
