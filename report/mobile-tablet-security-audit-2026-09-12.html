Executive Summary

Highest risk: phone behavior is not defined consistently. JavaScript uses 700px while several CSS and asset decisions use 780px. Widths 701-780px can receive phone CSS with tablet JavaScript and tablet frames.
High

Breakpoint split

701-780px is a mixed phone/tablet mode. This can explain incorrect heights, section stops, and composition on narrow tablets.

Medium

Compact loading gate bypass

Compact scroll can outrun decoded frames. Fast tablet scroll may show stale or blank frames.

Medium

Tablet CSS coverage

Several sections have no tablet-specific rules and fall back to desktop or broad compact rules.

High

Next dependency advisories

Next 16.2.10 pulls vulnerable transitive versions. Current app does not use several affected features, but upgrade remains recommended.

Confirmed Findings

HIGH | F-01

700px vs 780px breakpoint mismatch

Evidence: src/components/AnimationLab/frameDirMobile.ts:74 uses 700px; timeline.ts:2006 uses 780px; phone CSS appears in 07-hero.css:325, 04-digital.css:329, 05-intro-statement.css:60, and 02-main-start.css:43.

Effect: 701-780px can receive phone CSS, tablet frame assets, tablet loading policy, and phone carve values.

Fix: Select one canonical boundary. 780px is likely intended because carve logic already uses it. Update JS and tests together, then validate at 700, 701, 780, and 781px.

MEDIUM | F-02

Compact loading gate bypass

Evidence: src/components/AnimationLab/AnimationLab.tsx:1208-1212 clears the gate for compact frames that are not exact settled frames.

Effect: Fast touch or wheel movement can request frames before decode completes. Tablet has larger frame payloads and is more exposed.

Fix: Add a narrow readiness gate or nearest-decoded-frame fallback. Test fast touch, wheel, and section transitions at phone and tablet widths.

MEDIUM | F-03

Uneven tablet CSS coverage

Evidence: no tablet-specific rules in digital, glance, bridges, ocean banner, nonfinancial carousel, and financial sections; see src/components/AnimationLab/styles/.

Effect: Tablet often falls through to desktop sizing or broad compact rules. This can produce incorrect typography, section heights, and stop points.

Fix: Test every section at 768x1024 and 1024x768. Add only targeted tablet rules where measured layout fails; do not copy phone rules wholesale.

MEDIUM | F-04

Touch handoff is abrupt

Evidence: compact navigation intercepts touch movement in AnimationLab.tsx:629-912; reader matching is defined in compactNavigation.ts:4-5.

Effect: At inner reader edges, the next swipe can jump sections without momentum carry-over. This is more noticeable on tablet.

Fix: Model reader edge state explicitly and transfer gesture ownership only after boundary direction is confirmed.

LOW | F-05

Community viewport unit mismatch

Evidence: 18-community.css:109 uses 100svh, while compact media uses 100dvh in 01-shared-shell.css:199-204.

Effect: iOS toolbar changes can leave the community stage shorter than the canvas.

Fix: Validate on iOS Safari; use the same viewport strategy as the compact canvas if a gap is reproduced.

LOW | F-06

Mobile progress indicator visibility

Evidence: 01-shared-shell.css:624-637 keeps a 3px indicator at 1.1% from the right on every viewport.

Effect: It is difficult to see on narrow phones and may compete with the edge gesture area.

Fix: Set a fixed compact inset or hide it on phones after confirming product intent.

Intentional Differences

  • Lenis is disabled for all compact widths in AnimationLab.tsx:603; this avoids touch inertia conflicts.
  • Strategy uses native inner scrolling for compact widths in StrategyLayer.tsx:123-127.
  • Financial tablet keeps staggered reveal while phone removes it; this is a deliberate performance/readability tradeoff.
  • CommunityLayer.tsx:202 always includes data-lenis-prevent; harmless while Lenis is disabled on compact.
  • Dead branches exist in timeline.ts:411-419 and LeadershipLayer.tsx:148-158; cleanup only, not current behavior defects.

Recommended Fix Order

  1. Unify the phone breakpoint. This is highest priority because it affects CSS, frame assets, carve values, loader policy, and section geometry.
  2. Run a section-by-section tablet pass at 768x1024 and 1024x768. Record exact section entry, settled, and exit positions.
  3. Fix compact frame readiness. Verify rapid touch and wheel movement cannot display stale or blank frames.
  4. Fix tablet touch handoff at inner-reader boundaries.
  5. Normalize viewport units in Community and check iOS Safari toolbar behavior.
  6. Upgrade Next and transitive dependencies in an isolated security change. Rebuild and rerun all responsive checks.
  7. Harden or remove the third-party script dependency with SRI/self-hosting.
